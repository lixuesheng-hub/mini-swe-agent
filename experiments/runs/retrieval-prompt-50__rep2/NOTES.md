# 实验：prompt 检索提示全量 50 题 —— rep2（方差复跑）

**假设**：`retrieval-prompt-50` 的 41/50（82%，配对 p=0.003）不是单次好运；同配置重跑点值应接近，且对基线的显著优势复现。
**唯一变量**：无（与 rep1 逐配置相同：`swebench_webhint.yaml`、doubao-lite、`-w 2`、step_limit 250）。
数据集用缓存 repo id `MariusHobbhahn/swe-bench-verified-mini`（已核对与本地 parquet 50 题逐题一致；原因：当日直连 HF 不通，
本地 parquet 目录不被 datasets 识别，走 socks5h 代理 + 缓存 repo，与首跑加载的是同一数据）。

## 两次重复的稳定性（核心）

- 两次都过 **38**，两次都挂 **5**，单题翻转 **7**（11815/12308/12406/10673/8548/9229/9461）。
- rep1 vs rep2 配对 p=1.00：两次 run 自身无系统差异，7 题翻转即 ±7 题/run 的经验随机翻转范围（比先前 ±3–5pp 的粗估略大，约 ±7pp 单题级）。
- **稳定结论**（两次一致）：交集 38/50 = 76%；并集 45/50 = 90%；合并 n=100 为 **83/100 = 83%**。
- 对基线的显著优势两次独立复现（p=0.0034 / 0.0018），结论稳健。
- 关键个案：8056/8638 两次都过（探针结论稳定）；**早提交型 8269/8475 两次都挂**；7985 两次都挂；
  10673 rep1 病态循环耗尽、rep2 正常通过 → 10673 是随机退化，不是提示词的系统性副作用；
  11815 rep1 挂 rep2 过（基线过）→ 随机翻转。

## 结论

1. 提示词变体的提升稳健：点值 82% / 84%（合并 83%），两次配对检验均显著；"检索前置"结论不再依赖单次 run。
2. run 间噪声量化为 ~7 题翻转/50；报告应同时报交集（76%，保守）与合并率（83%）。
3. 每 run 约 1 题陷入 250 步耗尽（10673 / 7985，位置随机），是独立于检索策略的稳定性问题
   ——为阶段 4 早停 policy 提供了证据（2 个 run 2 例，空补丁即 0 分）。
4. 早提交型失败（8269/8475）两次复跑均未解决，T2 gate 优先级不变。
