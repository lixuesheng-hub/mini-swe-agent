# 实验：prompt 检索提示全量 50 题（webhint）

**假设**：在系统提示词中加入"先用 curl 查上游 issue/PR 讨论与修复，理解后自己复现并验证"一段（不注册任何新工具），
会让弱模型把检索从"卡住后的被动动作"变成"默认早期动作"，从而提高 resolved 率。
依据：n=2 探针 2/2 通过，8056 从 100 步失败变 21 步成功。

**唯一变量**：`agent.instance_template/system_template` 换成 `experiments/verified_mini_baseline/swebench_webhint.yaml`
（比基线多一段 "Searching for upstream context"）；`model.extra_tools` 为空，纯 bash，无工具。
模型、数据集、并发（-w 2）、step_limit(250) 全部与基线一致。

**数据**：SWE-bench verified-mini 50 题（与基线、工具版同一批题，可配对）。

## 结果

| 指标 | 基线 | 工具版 retrieval-tool-50 | **本次 prompt 版** |
|---|---:|---:|---:|
| resolved | 30/50 = 60% | 36/50 = 72% | **41/50 = 82%** |
| Wilson 95% CI | [46%, 72%] | [58%, 83%] | [69%, 90%] |
| vs 基线配对（新过/新挂） | — | 7 / 1 | **12 / 1** |
| McNemar 双侧 p | — | 0.070（不显著） | **0.0034（显著）** |
| django / sphinx | 18 / 12 | 20 / 16 | 22 / 19 |
| 步数中位 / 均值 | 34 / 46 | 32 / 46 | **28 / 37** |
| 回归实例（回归数） | 6（11） | 4（8） | 5（9） |
| 截断次数 | 22 | 34 | 16 |
| 重复命令 | 16 | 23 | 230（其中 214 集中在 10673，见下） |
| 检索实例 | 4 | 22 | **45** |
| 空补丁 / infra | 0 | 0 | 1 / 0 |

harness 实际评测 49 题（10673 跑满 250 步 `LimitsExceeded`，无补丁，自动跳过），按 50 题口径计失败 = 41/50。

### 配对明细

- **prompt vs 基线**：12 个翻盘（django 11848/11885/11964/12273/12308；sphinx 10323/7590/7748/8056/8548/8638/9230），
  1 个翻盘失败（django-11815）。McNemar p=0.0034。
- **prompt vs 工具版**：7 赢 2 输，p=0.18（方向上提示词更优，但二者差距尚不显著）。
  值得注意：sphinx-9229 是工具版新挂、prompt 版通过；sphinx-10673 反过来（工具版过、prompt 版耗尽）。

## 结论

**假设成立，且是项目第一个通过同题配对显著性检验的变体**：一句零代码的提示词带来 +22pp（60%→82%），
p=0.0034；同时步数中位从 34 降到 28，检索实例从 4/50 升到 45/50。
与 n=2 探针一致地支持核心论断：**决定成败的是"让检索成为默认早期动作"，而非工具本身**；
"给工具 ≠ 会用工具"（工具版检索实例仅 22/50、提升不显著）。

**不能过度声称的部分**：
1. 这是单次 n=50 的结果，单题随机翻转 ±3–5pp（hard-case-rerun 证据）；prompt 版自身的 run 间方差尚未测（待 rep2）。
2. **开卷收益**：45/50 实例检索了上游，提升中相当部分属于 lookup 成功而非独立解出；报告需分开陈述。
3. prompt 比工具版"更好"目前 p=0.18，不能下结论。

## 负结果与异常

- **sphinx-10673 病态循环（解释仪表盘 230 次重复中的 214 次）**：该实例在第 6 条命令后，
  把同一条 `grep -rn "genindex|modindex|search" ...`（输出正常、returncode 0）重复执行 259 次，
  直到 250 步 `LimitsExceeded`、空补丁。全程仅 1 次 curl，**不是检索/限流导致**，
  而是单实例的模型退化循环（疑似 API 在特定上下文下返回重复响应）。该题工具版为 resolved——
  是 prompt 版唯一明确"新丢"给工具版的题，也是单次重复实验需要复跑的理由之一。
  剔除该实例后，其余 49 题重复命令合计 16 次，与基线持平。
- **django-11815 唯一新挂给基线**：41 步正常提交（17 次 curl），属随机翻转/解法偏差，需 rep2 确认。
- **早提交型失败仍未被修复**：sphinx-8269（21 步、5 次 curl）、sphinx-8475（18 步、4 次 curl）依旧失败。
  检索提示提高了查资料的概率，但管不住"急着交卷" → 提交 gate（T2）的必要性再次得到验证。

## 踩坑与环境

- 火山方舟 Coding Plan 端点直连（unset 全部 proxy）；`-w 2`；全程无 AccountQuota / burst 限流。
- 跑批时长约 2h05m；判分约 20min（max_workers 2，49 题，0 infra error），判分时代理走 socks5h:1080。
- 断点续跑工作正常（preds 已存在的实例跳过）。
